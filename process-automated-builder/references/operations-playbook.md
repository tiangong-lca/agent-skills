# Process authoring operations

Use `dataset process contract` to inspect the installed schema/rules and supported checks. Search/read exact existing data before deciding to author a new object. Write canonical content from evidence, then use validate, diff and explicit patch where appropriate. Choose create or save from the user's intended effect; never upsert on a read failure or increment a version merely to resume work.

Annual supply requires an evidenced quantity, unit and period: there is no reference-flow amount fallback. Unknown stays unknown through the actual owner's supported representation. A validation invocation's success is not publication readiness; inspect its validation layers, gaps and not-checked scope. Managed Foundry authoring/repair runs only through its current returned actions and qualified runtime. Do not fabricate its reports or bypass an unavailable admission gate.

Remote reference checks require selected exact evidence. Following a confirmed write, read back its exact target; an unknown effect must recover the original intent before another write. Review submission and Release publication are distinct later operations.

If the selected runtime emits sentinel volumes or lacks the required validation layers, report qualified adoption as incomplete; never hand-edit an empty array or bypass the runtime.
