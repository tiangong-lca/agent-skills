# LCA Study

Build a research object around an explicit Model. Keep the goal, functional unit, boundary, evidence, assumptions and actual calculation inputs connected. Start from the user's current materials; an existing Model or online Study is not required. A completed calculation supports analysis, not scientific certification.

## Start at the available evidence

Inspect the user's goal and existing files first. Resume from completed work; ask only for missing information that changes the model or interpretation. Keep an editable research brief and a source-linked inventory in the user's working directory, using readable documents or tables suited to the materials. Do not introduce a mandatory Study schema, per-step hashes or a revision workflow for local drafts. Keep raw source files intact and separate from extracted data and assumptions.

Before CLI operations, run this package's `node scripts/run-cli.mjs --runtime-info`. Use the environment owner's configured qualified installation; do not discover a PATH/sibling CLI, install a different version or approve the runtime's own identity. Read the selected command's help before constructing inputs. Missing commands require a compatible qualified installation; preserve completed research work while the environment owner supplies it. Installation integrity is an environment responsibility, not a new field in the user's research documents.

Local preparation, calculation and saved-result reads do not need authentication. Before remote discovery or reads, use `auth status --json`; if login is required, hand `auth login` to the user in a trusted terminal. Do not collect credentials. Before authorized account-sensitive writes use `auth doctor-auth --json`, keeping actor, client and destination fixed. Follow the CLI's current input contracts and returned next actions rather than assembling direct HTTP, SQL or queue calls.

## Research workflow

1. **Define the analysis.** Establish the product or service, purpose, functional unit and reference amount, system boundary, geography, period and intended comparison. Distinguish a measured inventory from an illustrative scenario. Do not ask the user to select backend protocols or identifiers before understanding the business question.
2. **Gather materials.** Ask for relevant bills of materials, production records, energy and transport records, specifications and existing studies. Read [evidence intake](references/evidence-intake.md) when guiding a data owner or organizing a mixed collection. A delegated intake skill returns source locations and scope; it does not create numerical facts or publish datasets.
3. **Extract modelable evidence and identify gaps.** Read [evidence extraction](references/evidence-extraction.md). Preserve source locations, original values/units, denominators, periods, uncertainty and justified conversions. Separate measured data, derived values, proxies and assumptions. Ask focused questions for critical missing amounts or boundaries. Absence in a source is not a zero. Continue independent extraction while awaiting answers.
4. **Build foreground processes and the Model.** Map actual operations, inputs, outputs and direct elementary exchanges. Use the CLI to discover Flow and supporting unit/property data and validate the modeled content. Preserve allocation and reference quantity meaning. Link only explicitly selected Process instances; unresolved demands need evidence or a declared cutoff. Local authoring stays local until an explicitly authorized `create` or `save`; calculation does not imply publication.
5. **Select and connect background processes.** Search for relevant state-code `100` Processes, compare their technology, geography, period and reference unit, then read exact selected versions. Do not select by the `LCI result` type label. Read available results and obtain the complete published LCI through CLI `dataset process results/get-result`; metadata or LCIA scores alone do not supply an inventory. Record selection reasons. Treat that LCI as the background's aggregate per published reference quantity: scale it to demand, preserve signs and units, and do not traverse or allocate its original upstream system again. The engine never chooses providers across the database.
6. **Calculate and analyze.** Read [Model calculation](references/model-calculation.md). Prepare complete inputs, calculate a new Run, then read its actual results and axes. Interpret numerical findings with units, scope, method and source evidence. Normal absent factors in a complete verified LCIA method mean no contribution for those Flows to that method; do not call this a coverage gap, warn, or label scores incomplete. Missing/corrupt method files, incomplete inventories, unresolved connections or invalid values remain real failures. Scenario changes produce new Runs; preserve earlier inputs/results without forcing unrelated draft work to restart.
7. **Generate and inspect the research report.** Read [report composition](references/report.md). Prepare editable JSON from the selected Model, actual Run results, evidence and interpretation, including the requested language text. Invoke `report render` through the configured CLI to generate a self-contained HTML report with embedded model visualization. Show one language at a time with a Chinese/English switch. Inspect both interactive content and print presentation; use the browser’s Print / Save as PDF for PDF delivery. Rendering does not compute, translate or certify the research.

If the user requests an existing online Study, frozen scenarios, contribution/comparison analysis, report review, finalization or named sharing, read [hosted Study](references/hosted-study.md). Those service operations have their own supported protocols and recovery; do not silently create an online Study to satisfy a standalone Model calculation. Keep old immutable reports and recovery receipts unchanged.

## Research handoff

Return the HTML report and editable report JSON when reporting is in scope, any actually exported PDF, the modeled goal and scope, files produced, data/source selections, material assumptions and unresolved questions, actual Run locations or IDs, and findings with units and method identities. State what was calculated versus merely prepared, which environment executed it, and the concrete next action. A failed or unknown remote mutation must follow the CLI's original-request recovery path; neither a new input file nor a new key resolves uncertainty.

Keep engineering execution, scientific interpretation, approval and external sharing separate. Perform only the requested scope; dataset publication and report disclosure require their own supported, authorized action.
