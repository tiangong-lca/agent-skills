# LCA Study

## Choose the response language first

Before setup guidance or research questions, follow the user’s explicit language preference; otherwise use the language of their substantive conversation. Respond in Chinese to Chinese requests and English to English requests, using one language at a time. For mixed-language messages, retain the established preference or follow the latest substantive request; ask briefly only when the preference is genuinely unclear. Switch when the user asks. English Skill text, source documents, filenames and CLI output do not change the reply language. Keep commands, identifiers, original evidence values and source quotations intact; explain them in the selected language. Use that language for questions, progress and summaries, and as the report’s initial language unless the user requests another. Bilingual report content and its language switch remain separate from bilingual chat.

## Research principle

Build a research object around an explicit Model. Keep the goal, functional unit, boundary, evidence, assumptions and actual calculation inputs connected. Start from the user's current materials; an existing Model or online Study is not required. A completed calculation supports analysis, not scientific certification. Use the supplied LCIA methods, factors and calculation engine as trusted infrastructure; judge background and method applicability to this study. Choose the next useful action from the available evidence, not from an obligation to finish every workflow step.

## Start at the available evidence

For a first-time user without the Skill, CLI or calculation environment, read [getting started](references/getting-started.md). Complete available installation steps and verify readiness before CLI work; reuse the installed `tiangong-lca` command and report unavailable release artifacts precisely. Once configured, continue here without repeating setup.

Inspect the user's goal and existing files first. Resume from completed work; ask only for missing information that changes the model or interpretation. Keep an editable research brief and a source-linked inventory in the user's working directory, using readable documents or tables suited to the materials. Do not introduce a mandatory Study schema, per-step hashes or a revision workflow for local drafts. Keep raw source files intact and separate from extracted data and assumptions.

Call `tiangong-lca` directly. At setup or the start of a new study, check the installed version and recommend the latest stable CLI using [getting started](references/getting-started.md). A compatible installed version can continue; record the version used without locking the research to it. Check `tiangong-lca --help` once when starting in a new environment, then read the needed command’s `--help --json`. Install or update through the official CLI guidance when a required command is missing. Ordinary research needs no runtime expectation file, hash or fixed Node identity. Optional `node scripts/run-cli.mjs` forwards to the same PATH command.

Local preparation, calculation and saved-result reads do not need authentication. Before remote discovery or reads, use `auth status --json`; if login is required, hand `auth login` to the user in a trusted terminal. Do not collect credentials. Before authorized account-sensitive writes use `auth doctor-auth --json`, keeping actor, client and destination fixed. Follow the CLI's current input contracts and returned next actions rather than assembling direct HTTP, SQL or queue calls.

## Research workflow

1. **Orient the study.** Understand the product/service, intended use of the results and available materials. Offer provisional scope and functional-unit suggestions in business language; refine them as evidence arrives. Distinguish confirmed facts, proposals and adopted assumptions. A product-only request calls for material intake, not an invented baseline or a demonstration report.
2. **Guide material collection.** Read [evidence intake](references/evidence-intake.md) when starting intake. Turn the product and provisional boundary into a small, prioritized request: name useful business records, explain what each will establish and suggest where to obtain it. Start with a few available files in any readable form; help users who do not know what to provide. After each batch, summarize what it answers and request only the next material gap, with an alternative source or collection method. A complete questionnaire or standard workbook is not a prerequisite. A delegated intake skill returns source locations and scope; it does not create numerical facts or publish datasets.
3. **Extract modelable evidence and identify gaps.** Read [evidence extraction](references/evidence-extraction.md). Preserve source locations, original values/units, denominators, periods, uncertainty and justified conversions. Separate measured data, derived values, proxies and assumptions. Ask focused questions for critical missing amounts or boundaries. Absence in a source is not a zero. Continue independent extraction while awaiting answers. If a necessary amount or scope decision is unavailable, return the specific question and resume point; an autonomous execution goal must preserve this handoff rather than manufacture completion.
4. **Develop foreground and background together.** Map actual operations, inputs, outputs and direct elementary exchanges. Discover background candidates while choosing foreground Flows, so compatible existing identities can be reused without changing the actual demand. Read [background modeling](references/background-modeling.md) for reference selection, explicit links and ordinary Process proxies/conversions. Use the CLI to discover Flow and supporting unit/property data and validate the modeled content. Preserve allocation and reference quantity meaning. Link only explicitly selected Process instances; unresolved demands need evidence or a declared cutoff. Local authoring stays local until an explicitly authorized `create` or `save`; calculation does not imply publication.
5. **Select and connect background processes.** Search for relevant state-code `100` Processes, compare their technology, geography, period and actual reference Flow/quantity/unit, then read exact selected versions. Match the published LCI reference basis to the selected process and demand. Connect matching ports directly; represent justified equivalence, proxy substitution or physical conversion through an explicit ordinary Process with stated quantities and evidence. An unknown reference basis cannot be repaired by inventing a conversion. Do not select by the `LCI result` type label. Read available results and obtain the complete published LCI through CLI `dataset process results/get-result`; metadata or LCIA scores alone do not supply an inventory. Record selection reasons. Treat that LCI as the background's aggregate per published reference quantity: scale it to demand, preserve signs and units, and do not traverse or allocate its original upstream system again. The engine never chooses providers across the database.
6. **Calculate and analyze.** Read [Model calculation](references/model-calculation.md). Prepare complete inputs, calculate a new Run, then read its actual results and axes. Interpret numerical findings with units, scope, method and source evidence. Normal absent factors in a complete verified LCIA method mean no contribution for those Flows to that method; do not call this a coverage gap, warn, or label scores incomplete. Missing/corrupt method files, incomplete inventories, unresolved connections or invalid values remain real failures. Use returned diagnostics to correct the specific input; a failed connection is not evidence that multiple instances are unsupported. Preserve the smallest failed input and unresolved error when no supported correction is available. Scenario changes produce new Runs; preserve earlier inputs/results without forcing unrelated draft work to restart.
7. **Generate and inspect the research report.** Read [report composition](references/report.md). Prepare editable JSON from the selected Model, actual Run results, evidence and interpretation, including the requested language text. Invoke `report render` through the installed CLI to generate a self-contained HTML report with embedded model visualization. Show one language at a time with a Chinese/English switch. Inspect both interactive content and print presentation; use the browser’s Print / Save as PDF for PDF delivery. Show conversion/proxy nodes and their assumptions. When a finding changes, update the current research brief and report JSON, regenerate the affected HTML, and mark superseded claims as withdrawn in retained history. Rendering does not compute, translate or certify the research.

For a calculation-only request with an existing Model, reuse its inputs and stop after returning the actual results; do not require evidence intake or a report that the user did not request.

If the user requests an existing online Study, frozen scenarios, contribution/comparison analysis, sensitivity, uncertainty, method assessment, report review, finalization or named sharing, read [hosted Study](references/hosted-study.md). Those service operations have their own supported protocols and recovery; do not silently create an online Study to satisfy a standalone Model calculation. Keep old immutable reports and recovery receipts unchanged.

## Research handoff

Return the HTML report and editable report JSON when reporting is in scope, any actually exported PDF, the modeled goal and scope, files produced, data/source selections, material assumptions and unresolved questions, actual Run locations or IDs, and findings with units and method identities. State what was calculated versus merely prepared, which environment executed it, and the concrete next action. A failed or unknown remote mutation must follow the CLI's original-request recovery path; neither a new input file nor a new key resolves uncertainty.

Keep engineering execution, scientific interpretation, approval and external sharing separate. Perform only the requested scope; dataset publication and report disclosure require their own supported, authorized action.
